## Cloudflare и WebView2 (проверить на Windows)

- Страницы Modland лаунчер берёт через WebView2 (настоящий движок Chrome, IP пользователя), а не через HttpClient.
- Если сайт показал проверку («Один момент…», «Проверяем, человек ли вы»), `ChallengePageDetector` ставит источнику `NeedsHumanCheck`, лаунчер показывает окно с этой страницей, проверку проходит пользователь. Автоматических решателей нет и не будет.
- Проверить на Windows: проходит ли WebView2 Modland без проверки; сколько живёт cookie после её прохождения; хватает ли общего профиля WebView2 для окна загрузки и для чтения страниц.
- Запросы редкие, с кэшем (проверка обновлений раз в несколько часов).

## Установка (проверить на Windows)

- Предположение: BeamNG подхватывает `.zip` из папки `mods` как есть (без распаковки). Проверить на настоящей игре.
- Отключённый мод менеджер переносит в свою папку рядом с `mods` и не трогает `db.json` игры. Проверить, не считает ли игра перенесённый файл потерянным и не ломает ли это сохранения. Решение про `db.json` отложено до проверки формата.
- Проверить права записи в папку игры и поведение при запущенной игре (файлы могут быть заняты).

## Уточнения по присланным страницам (2026-10-13)

- **Modland**: сортировка ленты — date published / last updated / downloads / trending / rating / likes, по умолчанию **last updated**; фильтр времени — today / last week / all time. Для проверки обновлений нужна именно лента по умолчанию (last updated): новое и обновлённое поднимается вверх. Страница поиска `/search/{q}` разбирается тем же разбором карточек (проверено на «sienna», 6 карточек).
- **ModsGaming**: поиск `/search/?q={запрос}&t=0` подтверждён образцом. Результаты — таблицы (`td.search-td-1` ссылка, `span.search-span-2` дата), размера и автора в выдаче нет, их даёт карточка. В выдаче бывают другие игры — берём только `/load/beamng_drive/`. Поиск включён.
- **ModsFire**: два шага. Шаг 1 — кнопка «Generate Link» (`/download/{id}/{токен}`, таймер ~5 с). Шаг 2 — кнопка `id="downloadnow"` на `/d/{id}`; если загрузка не началась, сайт просит нажать ещё раз. Оба шага показывают имя, размер и дату, лаунчер читает их только для сверки с ожидаемым файлом. Кнопки нажимает пользователь.
- **Непроверено (нужна игра)**: как BeamNG ведёт себя, если две ZIP в `mods` содержат одну и ту же папку `vehicles/<имя>/` (см. «Паки модов»).

## Паки модов

Модуль `Packs`: `PackContentReader` читает из ZIP списки `vehicles/<имя>` и `levels/<имя>` без распаковки, `PackOverlapAnalyzer` сравнивает новый архив с установленными модами и находит дубли среди включённых.

Нужно проверить на игре: что делает BeamNG, когда две включённые ZIP содержат одну и ту же папку `vehicles/<имя>/` (какая побеждает, есть ли ошибки в логе, ломаются ли конфигурации). До проверки менеджер только предупреждает о дублях и не выключает ничего сам.

## Платный контент на Modland

- Главный признак — значок «$» с подсказкой «Paid content» рядом с названием: и в карточке ленты, и в заголовке страницы мода. Метка `[PAID]` в названии не обязательна (три присланных пака её не имеют). Парсер ставит Paid по значку.
- Запасной признак — блок «External Download Links»: адреса лежат в `title="External Download - URL"` (у ссылок нет `href`, они открываются через окно-подтверждение). Ссылки на Patreon, Boosty, Ko-fi — платные; Discord и подобные не считаются ни файлом, ни платным.
- Платный пак показывается в поиске и в проверке обновлений, но не скачивается и не ищется на сторонах.

### Платный контент на остальных сайтах (проверено на сохранённых страницах)

- **ModsGaming**: признака платного в образцах (лента, карточка, поиск) нет. Слово «vip» там — раздел видео. Цена остаётся «неизвестно».
- **STMods**: тоже нет. Надпись «Бесплатно» на странице — реклама менеджера Ava, а не цена мода, её не учитываем. В описании BMW E34 есть «платный аддон» внутри архива — это частный случай, цену мода не меняет, при желании можно показывать как заметку.
- **ModsFire**: Premium ($0.99/мес) ускоряет скачивание, к цене мода отношения не имеет.
- Значок «$ Paid content» — особенность Modland. Если на другом сайте встретится платный мод, нужна страница с ним, чтобы добавить признак.

## Официальный репозиторий beamng.com/resources (просмотрен в браузере 2026-10-13)

- Движок XenForo Resource Manager. Ссылки на странице относительные (`resources/…`), корень — `https://beamng.com/`.
- Лента `resources/`: 100 модов на странице, ~1586 страниц, по умолчанию сортировка **Last Update**. Другие: `?order=resource_date` (Submission Date), `rating_weighted`, `download_count`, `title`. Страницы: `?page=N`. Категории: `resources/categories/…`.
- В карточке ленты: название, `span.version`, префикс (Alpha / Beta / Experimental), автор, категория, скачивания, подписки, «Updated». Дата в середине строки — дата создания, настоящее время обновления — в блоке `resourceUpdated`.
- Страница мода: **Unique ID** (например `MOKU3EJNG`) — тот же, что игра использует в `beamng:v1/showMod/{id}`; кнопки «Subscribe» (установка самой игрой), «Download Now 100.2 KB .zip» (`…/download?version=N`, прямая раздача сайтом), версия и размер. Платных кнопок и цен в просмотренных страницах не было; платный контент в официальном репозитории не наблюдался.
- Поиск XenForo отправляется POST-запросом с токеном; образца результатов нет, поэтому `SupportsSearch = false`. Лента и карточки работают.
- Проверить на Windows: совпадает ли Unique ID с идентификатором в списке установленных модов игры (`db.json`). Если да, привязку установленных модов к репозиторию можно делать точно, без подбора по названию.

## Папка пользователя игры (источники: официальный анонс «User Folder and Migration Changes», страница User Files)

- С версии **0.37** папка пользователя: `%LOCALAPPDATA%\BeamNG\BeamNG.drive\current\` (раньше `%LOCALAPPDATA%\BeamNG.drive\<версия>\`). Менеджер понимает оба варианта (`GameFolders`).
- Пользователь может **перенести** папку в своё место через лаунчер («Manage User Folder → Move to custom location»); путь тогда задаётся вручную. Автоопределение может не сработать — это нормально.
- Все моды, включая скачанные из репозитория, лежат в `mods/`. Существуют ли `mods/repo` и `mods/unpacked`, по документации неясно: **проверить на Windows**.
- При крупных обновлениях игра чистит папку пользователя: неизвестные файлы уходят в резервную папку, моды намеренно отключаются. Поэтому отключённые моды и резервные копии менеджера хранятся **вне** папки игры (`ModLayout.InAppFolder`), а не рядом с `mods`.
- Steam может удалять «неизвестные» файлы в папке пользователя, если она лежит внутри папки игры.

## Задачи на этап с Windows (обнаружены при ревизии, в ядре решить нельзя)

- **Один экземпляр приложения.** Блокировки в `ModInstaller` действуют внутри процесса. Два запущенных менеджера одновременно могут конфликтовать за файлы и настройки: нужен именованный Mutex при старте.
- **Занятые файлы.** `InstallError.InUse` определяется по коду ошибки Windows (32/33); поведение при запущенной игре проверить на реальной системе.
- **Антивирус** может задержать или удалить файл посреди установки: проверить, что временный `.part` и откат работают.

- [x] **Моды из репозитория BeamNG.** Архив, собранный репозиторием, содержит `mod_info/<Unique ID>/info.json`, и игра
  переносит его в `db.json`: `modID` (= Unique ID на beamng.com, например `M7P2C4JGW`), `modInfoPath`, а в `modData` —
  `version_string` (версия на сайте), `resource_id`, `tagid`, `title`, `username`, `last_update`, `resource_version_id`,
  описание и список хешей файлов. **Такой мод привязывается к репозиторию точно, без подбора по названию**, и проверка
  обновлений сравнивает `version_string` с сайтом.
- [x] **Превью внутри архивов есть:** у машин `vehicles/<имя>/default.jpg` и картинки конфигураций (`ADRO.jpg` рядом с `ADRO.pc`),
  у карт — картинки в `mod_info/<ID>/` и в папке уровня. Заглушка нужна только для модов, где картинок нет
  совсем (Traffic Reborn: `modType: unknown`, внутри только `lua`, `scripts`, `settings`); у скриптовых модов с картинками
  берётся их картинка.
- [x] **Игра умеет сама выключать моды после своего обновления** (`core_modmanager.getModsDisabledAfterUpdate` в логе):
  после крупного обновления часть модов может оказаться выключенной не пользователем. Менеджер должен это показывать, а
  не считать ошибкой.

- [x] **Игра читает ZIP как есть, без распаковки** (в логе `mountEntry -- /mods/<архив>.zip`, распакованных копий в папке
  пользователя нет). RAR и 7z игра не понимает: менеджер перепаковывает их в ZIP при установке (PLAN.md 7).
- [x] **Игра включает и выключает моды на ходу и сразу пишет db.json** (снимки при запущенной игре 2026-10-15: W164
  выключен в игре — через несколько секунд в db.json `active: false`; при запуске игра тоже перезаписывает файл).
  Список живёт в памяти игры, правку менеджера во время игры она затрёт: менеджер применяет изменения после закрытия
  игры (DESIGN_FLOWS.md 3.5).
- [x] **Игра не держит архивы модов занятыми** (запущена, скорее всего в меню): все 5 архивов открылись на монопольное
  чтение. Ставить, заменять и удалять моды можно и при запущенной игре. Не проверено: архив машины, загруженной на
  карте прямо сейчас (если он занят, ядро сообщит «файл занят» и ничего не испортит).
- [x] **Процессы запущенной игры:** `BeamNG.drive` (лаунчер) и несколько `BeamNG.drive.x64` (сама игра и её встроенный
  браузер). `GameProcess.IsRunning` смотрит только на `.x64`: лаунчер работает рядом с игрой и может остаться открытым
  после выхода из неё, а `db.json` он не держит.
- [ ] **Моды из встроенного репозитория** игра кладёт в `mods/repo/` (`fullpath: /mods/repo/<архив>`). Менеджер их видит
  и переключает флажком, файлы там не трогает (игра обновляет их сама). На живой игре ещё не проверено: в снятых
  данных таких модов нет. Распакованные моды (`mods/unpacked/<имя>/`) менеджер пока не показывает.

**Ещё не проверено:** что игра делает, если файл мода убрать из папки
(нужно, только если менеджер выключает мод переносом файла, см. STATUS.md); два архива с одной машиной; странные имена.
