# Переезд ModManager BeamNG на Rust + Tauri 2 + Svelte 5

Дата: 2026-10-21. Ветка: `refactor-rust-poc`. Заменяет прежний стек .NET 10 / C# / WPF.

## 1. Зачем и что получаем

Приложение делает то же, что версия 0.3.12, но на другом стеке: Rust-ядро, окно Tauri 2,
интерфейс Svelte 5 + TypeScript + Tailwind CSS 4 + shadcn-svelte. Моды остаются обычными
файлами игры, данные и настройки пользователя сохраняются.

Цели:

- полный паритет функций с 0.3.12 до выпуска v1; ни один сценарий не теряется;
- тот же каталог данных, те же форматы файлов, безопасный откат на старую версию;
- заметно меньше и проще поставка: один портативный exe, без .NET;
- Rust-ядро проверяется тестами без окна, интерфейс — без сети и игры;
- сохранённый фирменный вид: жидкое стекло, темы, виртуальная сетка на 5000 модов.

Не входит в v1:

- macOS и Linux (пользователь явно отказался);
- профили модов в интерфейсе (решение старого проекта: остаются фильтры);
- скачивание модов с сайтов, обход платных стен и капч;
- фоновый процесс при закрытом окне, трей, автозапуск.

## 2. Архитектура

Backend-authoritative: Rust владеет состоянием и правилами, Svelte — представление.
Команды и события типизированы; тяжёлые операции идут с прогрессом и отменой.

```
SvelteKit SPA (Svelte 5 runes, Tailwind 4, shadcn-svelte)
        │ команды + Channel-события, сгенерированные типы
Tauri 2 (src-tauri): состояние, команды, окна, WebView2, обновление
        │
bmm-domain    модели, настройки, библиотека, matching, версии, текст, атомарная запись
bmm-game      поиск игры, db.json, bmm_bridge (Lua), процесс игры, GameDbSync
bmm-install   zip/rar/7z, безопасная распаковка, превью, установка/откат, входящие
bmm-sources   HTTP с вежливостью, 4 адаптера сайтов, поиск, кэш страниц
bmm-updates   планировщик, координатор, проверка обновлений модов
bmm-appupdate latest.json, загрузка, SHA-256, подмена exe, откат
        │
файлы игры, %LOCALAPPDATA%\BeamModManager, HTTPS, WebView2
```

### 2.1. Раскладка репозитория

```

  src/                         SvelteKit: routes, фичи, компоненты, ipc, design
  src-tauri/                   окно, команды, события, capabilities, tauri.conf.json
  crates/
    bmm-domain/
    bmm-game/
    bmm-install/
    bmm-sources/
    bmm-updates/
    bmm-appupdate/
  fixtures/                    HTML-страницы сайтов, db.json, ini, latest.json, Lua
  design/                      макеты и демо-картинки (как раньше)
  docs/                        документы проекта и эта спека
  tools/                       icon, windows-диагностика, новые скрипты выпуска
  legacy/                      старый C#, тесты и старый CI — временно, до M7
```

`poc/` растворяется в корне, `src/` и `tests/` старого проекта переезжают в `legacy/`.
Старый `windows.yml` переносится в `legacy/.github/workflows/`, чтобы GitHub его не запускал.
В корне появляются новые workflows. `tests/fixtures` переезжает в корень как `fixtures/`.

### 2.2. Соответствие старым модулям

| Новый крейт | Старый код | Что переносим |
| --- | --- | --- |
| `bmm-domain` | `Core/Settings`, `Core/Library` (модели и `JsonLibraryStore`), `Core/Matching`, `Core/Text`, `Core/Versioning`, `Core/Safety/DurableFile`, `Core/Pricing` | настройки, библиотека, решения по дублям, названия, сравнение версий, атомарная запись |
| `bmm-game` | `Core/Game`, `Core/Library/GameDbSync` | поиск папки игры, `db.json`, версия игры, процесс, мост Lua, сверка `active` |
| `bmm-install` | `Core/Install`, `Core/Packs`, `Core/Previews`, `Core/Safety/ArchiveInspector`, `Core/Safety/CloudFiles` | установка, копии, удаление/возврат, разбор архивов, превью, безопасность |
| `bmm-sources` | `Core/Net`, `Core/Sources`, `Core/Search`, `Core/Hosts` | HTTP, вежливость, адаптеры Modland / ModsGaming / STMods / BeamNG, поиск |
| `bmm-updates` | `Core/Updates`, `Core/Library/UpdateCheckService`, `UpdateRunner`, `UpdateCoordinator`, `PageGuesser`, `BindingActions`, `BindingSuggester` | планировщик, проверка, панель сайтов, привязки |
| `bmm-appupdate` | `Core/AppUpdate` | манифест, загрузка, проверка, staged-обновление, откат |
| `src-tauri` | `App/App.xaml.cs`, `App/Services`, `Ui/*` (связка) | состояние, команды, окна, drag-drop, уведомления, demo-режим |
| `src/` | `Ui/*` (представление), `App/MainWindow.xaml` | экраны, карточки, панели, настройки, анимации |

Правила зависимостей: `bmm-domain` не знает про сеть, окно и игру. `bmm-game`, `bmm-install`,
`bmm-sources`, `bmm-updates` зависят от `bmm-domain`. `src-tauri` — единственное место, где
собираются все крейты и Tauri. Циклов нет.

### 2.3. Почему не иначе

- Тонкая Rust-оболочка с логикой в TypeScript быстрее на старте, но теряет 889 проверок старого
  ядра и уводит работу с путями и архивами в JS — для менеджера модов это недопустимо.
- Sidecar-процесс с HTTP/WS удобен для отладки, но добавляет второй процесс, порт, авторизацию
  и упаковку. Для одного десктопного окна это лишняя сложность.

## 3. IPC: команды, события, типы

Типы DTO экспортируются из Rust в TypeScript (`specta`/`tauri-specta`; если в M0 выяснится
несовместимость с текущими версиями — `ts-rs` или ручные типы с тестом формы). Имена в JSON —
`camelCase`, в Rust — `snake_case`.

### 3.1. Команды

| Команда | Что делает |
| --- | --- |
| `app_bootstrap` | настройки, сведения о среде, папке игры, предупреждения загрузки |
| `library_load` / `library_refresh` | снимок библиотеки, пересборка сверкой с папкой |
| `mod_details` | содержимое архива, прошлые версии, привязки, проверки |
| `mod_toggle` | включить/выключить: `db.json` или мост при запущенной игре |
| `mod_delete` / `mod_restore_deleted` / `mod_restore_version` | удаление с «Отменить», возврат из «Удалённых» и прошлых версий |
| `archive_inspect` | разбор zip/rar/7z: что внутри, новый/обновление/уже стоит, проблемы |
| `archive_install` | установка выбранного с копией прежней версии и «Отменить» |
| `search_start` / `search_cancel` | поиск по включённым сайтам, поток результатов |
| `match_decide` | «Это один мод» / «Это разные», навсегда |
| `updates_start` / `updates_cancel` | проверка обновлений, поток состояния сайтов |
| `update_bind` / `update_decline` / `update_dismiss` / `update_replace_page` | привязка страницы, отказ, пропуск версии, замена пропавшей страницы |
| `settings_get` / `settings_patch` | чтение и мгновенное применение настроек |
| `app_update_check` / `app_update_install` / `app_update_cancel` | проверка и установка новой версии программы |
| `modland_check_start` / `modland_check_close` | окно прохождения проверки Cloudflare |

Все команды возвращают `Result<T, AppError>`. `AppError { code, message, details? }` — без паник
и без показа сырых текстов исключений пользователю.

### 3.2. Потоки и события

Долгие операции принимают `Channel<T>` и `RequestId`:

- `install://progress` — фаза, сделано/всего, сообщение;
- `search://event` — сайт, пачка карточек, завершение, ошибка;
- `updates://event` — фаза, сайт, счётчики, найденные обновления;
- `app_update://event` — загрузка, проверка, распаковка, готовность, сбой.

Глобальные изменения состояния — события `library://changed`, `settings://changed`,
`game://changed`. Отмена — `CancellationToken` в состоянии Tauri; повторная команда с тем же
`RequestId` не запускает вторую операцию.

### 3.3. Правила

- Один длинный запрос — один `RequestId`; события не смешиваются между запросами.
- Большие списки передаются компактными DTO; картинки — не base64, а URL.
- Прогресс установки и поиска не блокирует окно: все тяжёлые операции — в `spawn_blocking`
  или отдельной tokio-задаче.
- Никакой команды «выполнить произвольный путь/команду»: только конкретные операции.

## 4. Rust-ядро

### 4.1. `bmm-domain`

- `settings`: схема 2, PascalCase, enum-числа; терпимое чтение, `Normalize`, атомарная запись,
  карантин `*.bad-<время>`. Новые поля — только необязательные, старый файл остаётся читаемым.
- `library`: модели `InstalledMod`, `ModBinding`, `CheckState`, `PageSearch`; схема 1,
  PascalCase, enum-строки; атомарная запись, `Batch`, карантин, запрет перезаписи занятого файла.
- `matching`: `DuplicateMatcher` (вес имени .50, автора .20, размера .15, превью .10, игры .05;
  Same ≥ .9, Maybe ≥ .7, общий файл = 1.0) и `matches.json` (`schema`, `items` с `a/b/decision/at`).
- `text`: название мода, версия, платность, нормализация.
- `versioning`: сравнение версий и размеров, решение «есть обновление».
- `atomic`: запись через временный файл с `fsync` и переименованием (порт `DurableFile`).

### 4.2. `bmm-game`

- Поиск игры: `beamng.log`, `BeamNG.drive.ini`, `startup.ini` → `UserPath`, библиотеки Steam.
- `db.json`: ключ — имя файла без `.zip` в нижнем регистре (только латиница, как Lua), запись
  только `active`, копия `db.json.bmm-bak`, запрет записи при запущенной игре, проверка
  mtime/размера перед заменой, сохранение неизвестных полей.
- `bmm_bridge`: ассеты Lua в крейте, сборка zip, `commands.json`/`state.json`, те же таймауты
  (2 с запись, 6 с живость, 1 с опрос, 6 с ожидание).
- `GameDbSync`: наложение `db.json` на библиотеку, сохранение выключенных, поведение для
  архивов, которых игра ещё не видела.

### 4.3. `bmm-install`

- `zip` через crate `zip`, 7z и RAR — через `sevenz-rust2` и `unrar`; если крейт не подходит,
  допустим запасной путь через `tar.exe` Windows, как в старом приложении. Решение фиксируется
  в M3 после прогона фикстур.
- Пределы: 50 000 записей, 20 ГБ распакованного, коэффициент 200 к 1 свыше 100 МБ,
  8 ГБ на установку, 6 ГБ / 64 мода на входящие, 10 минут на распаковку.
- Запрещены исполняемые файлы, `..`, абсолютные пути, ADS, управляющие символы, симлинки,
  зарезервированные имена Windows. Пути длиннее 260 символов и юникод поддерживаются.
- Превью: одна картинка из ZIP по правилам старого `PreviewPicker`, без полной распаковки,
  кэш по `sha256(имя|размер|mtime)`, `.none` для отсутствия.
- Установка: `.part`, SHA-256 при копировании, ротация копий, защита `mods/repo`, возврат
  любой копии и версии, «Удалённые».
- Входящие: разбор zip/rar/7z, вложенные zip до 64, бюджет распаковки, перепаковка обёрточной
  папки, слежение за «Загрузками» и своими папками.

### 4.4. `bmm-sources`

- `reqwest` + `tokio`, gzip, `encoding_rs` (cp1251), UA, 30 с, 16 МБ, только HTTPS.
- Вежливость на сайт: один запрос одновременно, пауза 1.5 с + джиттер 1 с, повтор на 429/503
  с `Retry-After`, кэш 64 страницы / 30 минут, 3 сбоя → 10 минут покоя, обнаружение капчи
  останавливает сайт до сброса.
- Адаптеры Modland, ModsGaming, STMods, BeamNG: сначала переносим регулярные парсеры старого
  ядра (при необходимости `fancy-regex`), проверяем на 23 реальных HTML-фикстурах. Если парсер
  станет нечитаемым — переводим адаптер на `scraper`, сохраняя те же результаты.
- Поиск: поток карточек по сайтам, таймаут сайта 20 с / 30 результатов, слияние дублей,
  ручные решения, цены, превью.
- Modland: страницы, которые не пускает Cloudflare, грузятся скрытым окном WebView2.

### 4.5. `bmm-updates`

- Планировщик: TTL 6 ч (1–168), 3–10 страниц ленты, 150 карточек на сайт, бюджет 5 минут.
- Координатор: один запуск, отмена, повтор не чаще раза в минуту, пауза после сбоя 5 минут,
  12 пачек, состояния сайтов.
- Привязки: подтверждение, отказ, подсказки, пропавшие страницы, «Пропустить версию»,
  «Найти замену», подбор страницы раз в 14 дней, не больше 20 за проверку.
- Никаких скачиваний модов: «Обновить» ведёт на страницу мода.

### 4.6. `bmm-appupdate`

- `latest.json`: только GitHub HTTPS, версия/URL/размер/SHA-256/заметки/дата, 1–400 МБ.
- Проверка версии, загрузка во временный файл, сверка размера и хеша, распаковка zip.
- Подмена того же exe с сохранением файла (номер файла не меняется), копия `previous.exe`,
  запуск новой версии с ожиданием выхода старой, откат при падении, `update-skip.txt`,
  удаление `Zone.Identifier`, одна операция за раз, без понижения версии.
- Совместимость с `latest.json` старого приложения: новая версия 1.0.0 сможет обновиться
  со старой 0.3.12, дальше обновляется уже сама.

## 5. Интерфейс

### 5.1. Каркас

- SvelteKit SPA (`ssr = false`, `adapter-static`), Svelte 5 runes.
- Своя рамка окна: перетаскивание, минимизация, разворот, закрытие, прилипание, Alt+Пробел;
  минимум 1000×680, размер и разворот сохраняются.
- Маршруты: `/` — Моды, `/updates` — Обновления, `/search` — Поиск, `/settings` — Настройки.
- Общие части: титульная строка, фон, левая навигация, «островок» фильтров/поиска,
  правая панель, тосты, диалоги, экран перетаскивания архива.

### 5.2. Экраны (полный паритет)

- **Моды**: карточки с превью и названием, фильтры «Все / Включённые / Нужно обновить /
  Не проверяются / Удалённые», поиск Ctrl+F, выбор и стрелки, пробел — включить/выключить,
  правая панель: файл, версия, «Для игры», «Внутри архива», «Прошлые версии», «Следить»,
  меню карточки, удаление с «Отменить».
- **Обновления**: доступные/скрытые/пропавшие страницы, панель проверки и сайтов,
  «Пропустить версию», «Не проверять», «Указать страницу», «Найти замену», «вы человек?».
- **Поиск**: запрос сразу на все включённые сайты, скелеты, карточки по мере ответов,
  одна карточка на мод, «возможно, тот же мод» с решением навсегда, платные моды, панель сайтов.
- **Настройки**: «Внешний вид», «Загрузка модов», «Папки», «Обновления», «Сайты»; применяются
  сразу и сохраняются.
- **Входящие**: окно проверки архива, новый/обновление/уже стоит, проблемы безопасности,
  установка с прогрессом, «Отменить».
- **Знакомство**: четыре шага при первом запуске, «Далее», «Пропустить», Esc.
- **Плашка обновления программы**: загрузка, проверка, готовность, перезапуск, сбой.

### 5.3. Внешний вид и движение

- Dark / Light / System; пять фонов: Night, Deep, Dusk, Forest, Graphite.
- Наборы «Красиво» (жидкое стекло) и «Быстро» (матовое); анимации, фон, огоньки, наклон —
  отдельно. Настройки движения соблюдаются.
- Стекло — CSS: `backdrop-filter`, градиентная кромка, внутренний блик, тени. WebGL-слой
  преломления добавляется только если на живом экране разница с WPF будет заметна.
- Виртуальная сетка: в DOM только видимые карточки (ориентир старого окна — около 12);
  2–6 колонок, адаптивность, плавная прокрутка, сохранение позиции.
- Тексты, пустые состояния, сбои, тосты — по правилам старого `DESIGN_COMPONENTS.md`.
- Клавиши: Ctrl+1/2/3, Ctrl+,, Ctrl+F, Ctrl+Z, Пробел.
- Доступность: видимый фокус, подписи, навигация с клавиатуры, `prefers-reduced-motion`.

### 5.4. Структура фронтенда

```

src/lib/stores/       settings, library, toasts, window, requests (runes)
```

## 6. Данные и совместимость

Каталог: `%LOCALAPPDATA%\BeamModManager` (не меняется).

| Файл | Формат | Правило |
| --- | --- | --- |
| `settings.json` | PascalCase, enum-числа, `SchemaVersion` 2 | читаем и пишем как старый; новые поля только опциональные |
| `library.json` | PascalCase, enum-строки, `Schema` 1 | структура сохраняется; неизвестные поля игнорируются |
| `matches.json` | `schema`, `items` (`a`, `b`, `decision`, `at`) | без изменений |
| `previews/`, `search-previews/` | файлы кэша | ключи и правила те же |
| `WebView2/` | профиль WebView2 | общий для скрытого и видимого окна Modland |
| `update/` | staged-обновление, `previous.exe`, `update-skip.txt` | совместимо со старым |
| `errors.log` | текстовый журнал | новые записи в том же виде |

Миграция:

- читатели терпимые: неизвестные поля игнорируются, битые значения заменяются умолчаниями,
  повреждённый файл уходит в `*.bad-<время>` и не теряется;
- новые возможности не требуют ломать схему; если понадобится `SchemaVersion` 3 — старые поля
  читаются, старый файл остаётся валидным для отката;
- библиотека после переезда не должна терять привязки, историю файлов и решения по дублям;
- одновременная работа старой и новой программы запрещена: обе берут один и тот же именованный
  мьютекс `Local\BeamModManager.Single`; вторая показывает понятное сообщение и выходит.

Удаление старой версии (документируется в README/INFO, выполняется пользователем или
деинсталлятором нового приложения, но не автоматически):

- удалить папку старого exe и сам `BeamModManager.exe`;
- удалить `%LOCALAPPDATA%\BeamModManager` только при полном удалении программы;
- удалить `mods\bmm_bridge.zip` из папки игры только при полном удалении;
- моды, `db.json` и папку игры не трогать. Новое приложение использует тот же `bmm_bridge.zip`,
  поэтому при обычном переходе его удалять не нужно.

## 7. Платформа и безопасность

- Tauri 2, `decorations: false`, `withGlobalTauri: false`.
- Строгий CSP: `default-src 'self'`; `img-src 'self' asset: http://asset.localhost data: blob:`;
  `script-src 'self'`; `connect-src ipc: http://ipc.localhost`; без `unsafe-eval`; без внешних
  скриптов и стилей. Ослабления — только точечно и с записью в спеке.
- Capabilities: главному окну только нужное (окно, события, opener). Фронтенду не выдаются
  `fs`, `shell`, `http`, произвольные пути. Окно Modland — без IPC, только отображение сайта.
- Все команды валидируют пути: разрешённые корни — папка игры/модов, каталог данных,
  выбранные пользователем папки. Канонизация, запрет выхода за корень, проверка архивов.
- Сеть: только HTTPS, ограничение размера, таймауты, никаких секретов в клиенте.
- Самообновление: только GitHub HTTPS, проверка размера/SHA-256, без понижения версии.
- Ошибки не роняют окно: журнал + понятное сообщение, как в старой версии.

## 8. Производительность

Ориентиры на сборочной машине без видеокарты (старые замеры в скобках):

- холодный старт до готового гаража — до 4 с; тёплый — до 2.5 с;
- 5000 модов: сброс фильтра/поиска — до 300 мс (было 0.14–0.3 с);
- переключение раздела — до 300 мс; IPC-снимок 5000 модов — до 200 мс;
- в DOM одновременно не больше 80 карточек;
- память на 5000 модах — до 300 МБ;
- поиск и проверка не блокируют UI; прогресс приходит пачками.
