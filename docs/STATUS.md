**Как убедиться, что всё цело** (нужен .NET 8 SDK):

```
dotnet run --project tests/BeamModManager.Core.Tests
```

Ожидается строка `Пройдено: 402, провалено: 0` (около минуты; `BMM_SKIP_FUZZ=1` пропускает долгий набор).
Если нет доступа к NuGet (как в среде разработки), сначала `dotnet restore --configfile <конфиг с пустыми
источниками>`, затем `dotnet run --no-restore ...`. Внешних пакетов у ядра нет.

## 2. Что заморожено

- **Ядро.** Не меняем без причины: сначала нужен реальный опыт на Windows. Исключение: пробелы из раздела 3.1.
- **Дизайн.** Решение принято: жидкое стекло, один фон, фото первичны, без профилей-раздела и логотипа.
  Material 3 отвергнут. Менять только по итогам проверки шейдера (DESIGN.md раздел 8).
- **Макет.** Опубликован как дизайн-артефакт у заказчика (10 досок). В репозитории только скрипты сборки;
  фотографии (образцы заказчика, права неизвестны) в репозиторий не кладутся, поэтому пересобрать макет
  можно только с этими фото (DESIGN.md раздел 12).

## 3. Что найдено при ревизии и не сделано

### 3.1 Ядро: нужно утверждённому дизайну, но не написано (можно без Windows)

Мелкие, чистая логика, тестируются на Linux. Делаются первыми, если появится желание до Windows.

1. **Ручные решения по дублям.** В поиске кнопки «Это один мод» и «Это разные» (DESIGN_FLOWS.md 6.6), а PLAN.md
   обещает «сохраняются навсегда». В ядре такого хранилища нет, `DuplicateMatcher` ничего не запоминает.
2. **Возврат конкретной версии и список копий.** В макете «Прошлые версии» с кнопкой «Вернуть» у каждой, а в
   ядре есть только `Backups(имя файла)` и `RestoreLatestBackup`: вернуть произвольную копию нельзя. Нет и списка
   копий удалённых модов («Удалённые моды» в DESIGN_FLOWS.md 3.4).
3. **Настройки, которые есть в дизайне, но нет в `AppSettings`:** «Жидкое стекло», «Анимированный фон»,
   порог «активных модов больше N» (по умолчанию 30, PLAN.md), «первый запуск пройден», размер окна.
4. **«Не проверять этот мод».** Сейчас это снятие привязки; нужно убедиться, что подсказки привязки
   (`BindingSuggester`) не возвращают её сами при следующей сверке.
5. **Профили.** `ProfileService` в ядре есть и проверен, а в дизайне раздела профилей нет (заменён фильтрами).
   Вопрос к заказчику (раздел 3.3, п. 1).

### 3.2 Нужны Windows (список для первого дня в разделе 4)

- Всё из [PHASE0.md](PHASE0.md): путь к папке модов, формат `db.json`, версия игры, поведение игры с ZIP в `mods`,
  две ZIP с одной папкой `vehicles/<имя>`, правила и ToS сайтов, перехват загрузки WebView2, Cloudflare.
- Из [AUDIT.md](AUDIT.md): регистр имён файлов на Windows, занятые файлы (код 32/33), антивирус посреди установки,
  один экземпляр приложения.
- Интерфейс: WPF-приложение, шейдер стекла (критерий: 60 кадров в секунду на встроенной видеокарте),
  запасной путь через WebView2, сочетания клавиш, диктор, масштабы Windows 125 и 150 %.
- Кнопка «Играть» (запуск через Steam, номер игры не проверен), автоопределение папки игры, определение версии игры.
- **SQLite-хранилище** (`ILibraryStore` пока только в памяти) и **RAR/7z → ZIP** (нужен SharpCompress): оба
  требуют пакетов NuGet, поэтому отложены.
- Разбор HTML сейчас без AngleSharp (самописный); решение оставить или перейти принимается, когда будут пакеты.

## 4. Первый день с Windows (порядок)

1. Поставить .NET 8 SDK и Visual Studio или Rider. `dotnet run --project tests/BeamModManager.Core.Tests`.
   Ожидаются 402 теста. Всё, что упало на Windows (регистр имён, пути, блокировки), записать в AUDIT.md.
2. Пройти [PHASE0.md](PHASE0.md) сверху вниз, отмечая пункты. Начать с «мод, положенный вручную в папку, виден в игре»
   и формата `db.json`: от них зависят этапы 1 и 2.
3. Создать `src/BeamModManager.App` (WPF + WPF-UI) с одним пустым окном; убедиться, что оно собирается вместе с ядром.
4. **Прототип стекла на одной панели** (DESIGN.md раздел 8): шейдер смещения, измерить кадры. От результата зависит,
   что станет режимом по умолчанию (жидкое или лёгкое) и нужен ли запасной путь через WebView2.
5. Выбрать стиль работы с данными: перенести `ILibraryStore` на SQLite (нужны пакеты), подключить `HttpPageFetcher`.
6. Сборка экранов в порядке этапов PLAN.md: гараж (этап 1), обновления (2–3), поиск (4), загрузка (5).
   Перед каждым экраном нарисовать недостающие состояния (раздел 3.4).

## 5. Правила на время заморозки

- Никаких новых функций и экранов.
- Документы можно исправлять, если найдена ошибка. Если в документе помечено «не проверено», не превращать
  это в утверждение без проверки на Windows.
- Тесты должны оставаться зелёными: перед любым коммитом ядра `Пройдено: 402, провалено: 0` (или больше).
