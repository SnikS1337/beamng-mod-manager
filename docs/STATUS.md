**Как проверить** (нужен .NET 8 SDK; окно собирается только на Windows с .NET 10):

```
dotnet run --project tests/BeamModManager.Core.Tests
dotnet run --project src/BeamModManager.App                          # на Windows: настоящий гараж
dotnet run --project src/BeamModManager.App -- --demo design/demo   # на Windows: выдуманный гараж с доски
```

Ожидается `Пройдено: 709, провалено: 0` (около минуты; `BMM_SKIP_FUZZ=1` пропускает долгий набор — тогда 703).
Если нет доступа к NuGet (как в среде разработки), сначала `dotnet restore --configfile <конфиг с пустыми
источниками>`, затем `dotnet run --no-restore ...`. Внешних пакетов нет ни у ядра, ни у окна.

**Как работает сборка на Windows.** Каждый push в `main` запускает задания: тесты ядра на Windows, сборку окна
со снимками в демо-режиме (`--demo design/demo --shot файл.png [--width] [--height] [--select «мод»]`) и проверку
самообновления. Снимки, журнал сборки и текст ошибки, если окно упало, уходят в ветку `ci-shots` (каждый раз заново,
одним коммитом); там же замеры большой библиотеки (`--many N --perf`, файлы `*.perf.txt`: запуск, фильтр, поиск,
переключение, память; `--soak` — 300 кругов действий). Проверка самообновления (`selfupdate`) собирает две версии как
выпуск, кладёт программу на другой диск в папку с русскими буквами и проходит четыре случая: обновление, новая версия
падает (возвращает прежнюю сама), новая умирает (прежнюю возвращает прежний процесс), нет прав на папку. Ход — в ветке
`ci-selfupdate`. Выпуск без зелёной проверки самообновления не делается.
Если оба задания зелёные и выпуск заказан (пометка `[release]` в описании коммита или «Run workflow»), третье собирает
готовую программу (один `BeamModManager.exe`, .NET ставить не нужно) и
заменяет ею выпуск `latest` на GitHub: архив `ModManagerBeamNG.zip` с «Как запустить.txt» (`tools/release/README.txt`).
Репозиторий приватный: архив скачивается, только когда вошли в GitHub.

## 3. Что найдено при ревизии и не сделано

### 3.1 Ядро: пробелы под утверждённый дизайн (закрыты 2026-10-14)

Четыре пробела, найденные при ревизии, закрыты и покрыты тестами (`CoreFixesTests.cs`, 56 тестов, из них 10 по итогам повторных проверок).
Интерфейс подключит их так:

1. **Ручные решения по дублям.** `MatchDecisionStore` (`Matching/MatchDecisions.cs`): «Это один мод» / «Это разные»
   по паре записей на сайтах, хранятся в JSON навсегда, пишутся атомарно, повреждённый файл откладывается в
   `.bad-<время>`. Решение сильнее признаков: `DuplicateMatcher.Compare(a, b, решения)`; `SearchService(..., decisions)` склеивает или
   разводит карточки (карточка, с которой пользователь сам объединил запись, важнее автоматической склейки),
   `Regroup(ответ, запрос)` пересобирает их сразу, без сети и в исходном порядке записей. При ошибке записи на диск в памяти остаётся прежнее состояние.
2. **Возврат конкретной версии и копии удалённых.** `ModInstaller.ListBackups / RestoreBackup / RestoreVersion`
   и `VersionHistory.For / Restore / Deleted / RestoreDeleted` (интерфейс берёт «Удалённые моды» из `VersionHistory.Deleted`,
   а не из сырого `ModInstaller.DeletedMods`). Копии ищутся под всеми прежними именами файла мода
   (`ILibraryStore.FileHistory`) и под именами с тем же названием мода; посторонние файлы в папке копий (desktop.ini) копиями не считаются; возврат версии с другим именем оставляет в папке одну включённую версию,
   сохраняет состояние «включён/отключён» и при сбое возвращает текущий файл на место.
   Ограничение: у вернувшегося из «Удалённых» мода новая запись без прежних привязок (запись удаляется вместе с файлом при сверке).
3. **Настройки внешнего вида и прочие.** `AppSettings`: жидкое стекло (иней, его сила и искры льда убраны 2026-10-16), что за панелями, затемнение,
   анимации, анимированный фон, огоньки, наклон фона за мышкой (выключен), порог «активных модов больше N» (30),
   «первый запуск пройден», размер окна (меньше минимума 1000 × 680 не сохраняется).
   Значения приводятся к допустимым, старый файл читается с умолчаниями, неверный тип поля даёт предупреждение.
   `AppearancePresets` («Красиво» / «Быстро», до 2026-10-16 — четыре набора со льдом): применить и определить текущий
   набор. Старые поля инея в файле настроек читаются без предупреждений и при сохранении пропадают.
4. **«Не проверять этот мод».** `BindingActions.Decline` снимает привязки, состояние проверок и пропуск версии и
   запоминает отказ, `BindingActions.Undo` возвращает всё снятое (кнопка «Отменить» в тосте); `BindingSuggester.Suggest/FindAsync(store, ...)` такому моду ничего не предлагают и не ищут.
   Подтверждённая привязка вручную отказ снимает, `ResumeChecking` возвращает подсказки.
5. **Профили.** Решено: раздела профилей в интерфейсе не будет, остаются фильтры. `ProfileService` в ядре
   проверен тестами и пока не используется интерфейсом; не удаляем, решим при сборке интерфейса.

### 3.1а Проверка уязвимых мест (2026-10-16)

- **Самообновление.** Прежде: программа на другом диске (D:) на время переноса оставалась без exe; упавшую новую версию
  не возвращали (прежнюю удаляли сразу при её запуске); ошибка до окна оставляла невидимый процесс, и следующий запуск
  говорил «уже открыт»; после подмены прежняя версия не могла догрузить свои части и не сохраняла настройки при выходе
  (сборка одним сжатым файлом). Всё исправлено и проверяется на Windows целиком.
  **Известное:** выпущенная 0.1.57 обновляется ещё по-старому, поэтому при переходе с неё на следующую версию прежняя
  может один раз показать «Что-то пошло не так» при закрытии и не сохранить размер окна. Обновление при этом встаёт.
- **Сайт изменился.** Страница мода, на которой разбор больше ничего не находит (а раньше находил), не считается «без
  изменений»: в отчёте «возможно, сайт изменился», мод проверяется снова. Ссылку на раздел сайта вместо мода окно
  «Указать страницу» не принимает (по адресу); страницу без версии и файла — тоже.
- **Папки.** Перенесённая папка пользователя игры в Steam (`startup.ini`, `UserPath`) находится сама; если папка выбрана
  вручную, а игра обновилась и берёт моды из папки новой версии — подсказка. Архивы «только в облаке» (OneDrive) не
  скачиваются ради картинки. Пропавшая посреди чтения папка — «не нашли папку», а не ошибка. Пути длиннее 260 символов
  (проверено тестами на Windows), русские буквы, значки и скобки в именах модов.
- **Большая библиотека.** Поиск по `db.json` был квадратичным (5000 модов — почти секунда на каждое перечитывание);
  папка читалась трижды. Сетка гаража и список «Обновлений» создавали карточку для каждого мода сразу и заново при каждом
  поиске; теперь только видимые (`CardGridPanel`, `RowListPanel`). Замеры на сборочной машине (без видеокарты), до → после:
  5000 модов — запуск 14,4 → 1,8–3,3 с, сброс поиска 7,9 → 0,14–0,3 с, память 736 → 260 МБ, «Обновления» с 306
  карточками 3 → 0,2 с; 300 модов — сброс поиска 2,3 → 0,1–0,3 с. Пороги стоят в сборке.
- **Плавность анимаций (бой 2026-10-16: «многие анимации будто в 15 кадров»).** Найденные причины: свечения наведения
  лежали внутри общего кэша карточки (каждый кадр наведения заново считал тени, фото и подписи), панели и разделы
  перерисовывались целиком на каждом кадре появления, стекло над фоном копировало всю сетку карточек. Исправлено
  кэшами на время движения и стеклом только над фоном (DESIGN.md 8, «Плавность анимаций»). **Замер `--frames` на
  сборочной машине доверия не заслуживает:** она без видеокарты, и разные машины GitHub дают разное (одна и та же
  сборка — от 2 до 50 кадров в простое); старая и новая сборка, запущенные по очереди на одной машине, неотличимы
  в шуме. Настоящие числа — только на компьютере человека.
- **Долгая работа.** Утечек не нашлось (300 кругов действий в окне: куча 7 → 9 МБ, дескрипторы те же; в тестах — сотни
  кругов, окна привязки, проверки по таймеру, прыжки часов); список прежних имён файла у мода ограничен 20.

### 3.3 Решения и открытые вопросы

**Решено 2026-10-14:**
- **Профили:** оставляем фильтры, «Наборов» не будет.
- **Название:** «ModManager BeamNG» (заголовок окна, текст первого запуска, README). Имена проектов и пространств имён в коде
  (`BeamModManager.*`) не меняем.
- **Лицензия:** не нужна. Репозиторий приватный, для личного использования, ничего не продаётся. Остаётся «все права защищены».
- **Ледяное стекло:** обкатано в бою и снято 2026-10-16: иней везде выглядел как грязь. Основной стиль — жидкое стекло
  в духе Apple (почти прозрачные капли); при первом запуске набор «Красиво», для слабых компьютеров — «Быстро».
- **Верх окна:** стандартной полосы Windows нет; кнопки окна — стеклянная капсула в правом верхнем углу
  (DESIGN_FLOWS.md раздел 2). У выбранной карточки нет отдельной обводки; кнопки «Играть» нет.
- **Включение и выключение модов** (решено 2026-10-15): как в самой игре, флажком `active` в `db.json`; файл остаётся в
  `mods`. Пишем только при закрытой игре, атомарно, с копией `db.json.bmm-bak`. Запасной путь — перенос файла в папку
  менеджера — только для архива, которого игра ещё не видела (`GameDbSync.SetEnabled`).
- **Проверка обновлений:** при запуске и по кнопке. Повторная проверка, пока программа открыта, есть в настройках, по

- **Фон:** выберем свой; до этого образец с неизвестными правами.

**Остаются открытыми:**

1. Значок приложения.
2. Подсказка при первом запуске; где показать «Удалённые моды» (предложено: «Настройки → Обновления → Копии»); фоновая проверка при закрытой программе;
   установка перетаскиванием архива; светлая тема; предложение «Выключить жидкое стекло?» при низком FPS.

## 5. Правила

- Документы исправляем, когда найдена ошибка. Помеченное «не проверено» не превращаем в утверждение без проверки на
  Windows.

  без предупреждений (`-warnaserror`).
