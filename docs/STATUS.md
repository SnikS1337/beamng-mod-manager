## 2. Что заморожено

- **Ядро.** Не меняем без причины: сначала нужен реальный опыт на Windows. Исключение: найденные баги.
- **Дизайн.** Решение принято: жидкое стекло, один фон, фото первичны, без профилей-раздела и логотипа.
  Material 3 отвергнут. Менять только по итогам проверки шейдера (DESIGN.md раздел 8).
- **Макет.** Опубликован как дизайн-артефакт у заказчика (19 досок: 9 экранов, Material 3 и 9 экранов «ледяное стекло»). В репозитории только скрипты сборки;
  фотографии (образцы заказчика, права неизвестны) в репозиторий не кладутся, поэтому пересобрать макет
  можно только с этими фото (DESIGN.md раздел 12).

Дизайн на данный момент закрыт: основной стиль «жидкое стекло», вариант «ледяное стекло» понравился и нарисован на
всех экранах, движение описано в [DESIGN_MOTION.md](DESIGN_MOTION.md). Решение, делать ли лёд основным стилем, ещё не принято.

## 3. Что найдено при ревизии и не сделано

### 3.1 Ядро: пробелы под утверждённый дизайн (закрыты 2026-10-14)

Четыре пробела, найденные при ревизии, закрыты и покрыты тестами (`CoreFixesTests.cs`, 53 теста, из них 8 по итогам повторной проверки).
Интерфейс подключит их так:

1. **Ручные решения по дублям.** `MatchDecisionStore` (`Matching/MatchDecisions.cs`): «Это один мод» / «Это разные»
   по паре записей на сайтах, хранятся в JSON навсегда, пишутся атомарно, повреждённый файл откладывается в
   `.bad-<время>`. Решение сильнее признаков: `DuplicateMatcher.Compare(a, b, решения)`; `SearchService(..., decisions)` склеивает или
   разводит карточки (карточка, с которой пользователь сам объединил запись, важнее автоматической склейки),
   `Regroup(ответ, запрос)` пересобирает их сразу, без сети и в исходном порядке записей. При ошибке записи на диск в памяти остаётся прежнее состояние.
2. **Возврат конкретной версии и копии удалённых.** `ModInstaller.ListBackups / RestoreBackup / RestoreVersion`
   и `VersionHistory.For / Restore / Deleted / RestoreDeleted` (интерфейс берёт «Удалённые моды» из `VersionHistory.Deleted`,
   а не из сырого `ModInstaller.DeletedMods`). Копии ищутся под всеми прежними именами файла мода
   (`ILibraryStore.FileHistory`) и под именами с тем же названием мода; посторонние файлы в папке копий (desktop.ini) копиями не считаются; возврат версии с другим именем оставляет в папке одну включённую версию,
   сохраняет состояние «включён/отключён» и при сбое возвращает текущий файл на место.
   Ограничение: у вернувшегося из «Удалённых» мода новая запись без прежних привязок (запись удаляется вместе с файлом при сверке).
3. **Настройки внешнего вида и прочие.** `AppSettings`: жидкое стекло, иней (+ сила, искры), что за панелями, затемнение,
   анимации, анимированный фон, огоньки, порог «активных модов больше N» (30), «первый запуск пройден», размер окна.
   Значения приводятся к допустимым, старый файл читается с умолчаниями, неверный тип поля даёт предупреждение.
   `AppearancePresets` (Лёд / Стекло / Матовое / Лёгкое): применить и определить текущий набор.
4. **«Не проверять этот мод».** `BindingActions.DeclineChecking` снимает привязки, состояние проверок и пропуск версии и
   запоминает отказ; `BindingSuggester.Suggest/FindAsync(store, ...)` такому моду ничего не предлагают и не ищут.
   Подтверждённая привязка вручную отказ снимает, `ResumeChecking` возвращает подсказки.
5. **Профили.** Решено: раздела профилей в интерфейсе не будет, остаются фильтры. `ProfileService` в ядре
   проверен тестами и пока не используется интерфейсом; не удаляем, решим при сборке интерфейса.

### 3.3 Вопросы заказчику

- **Название:** «ModManager BeamNG» (заголовок окна, текст первого запуска, README). Имена проектов и пространств имён в коде

**Остаются открытыми:**

## 4. Первый день с Windows (порядок)

1. Поставить .NET 8 SDK и Visual Studio или Rider. `dotnet run --project tests/BeamModManager.Core.Tests`.
   Ожидаются 456 тестов. Всё, что упало на Windows (регистр имён, пути, блокировки), записать в AUDIT.md.
2. Пройти [PHASE0.md](PHASE0.md) сверху вниз, отмечая пункты. Начать с «мод, положенный вручную в папку, виден в игре»
   и формата `db.json`: от них зависят этапы 1 и 2.
3. Создать `src/BeamModManager.App` (WPF + WPF-UI) с одним пустым окном; убедиться, что оно собирается вместе с ядром.
4. **Прототип стекла на одной панели** (DESIGN.md раздел 8): шейдер смещения, измерить кадры. От результата зависит,
   что станет режимом по умолчанию (жидкое или лёгкое) и нужен ли запасной путь через WebView2.
5. Выбрать стиль работы с данными: перенести `ILibraryStore` на SQLite (нужны пакеты), подключить `HttpPageFetcher`.
6. Сборка экранов в порядке этапов PLAN.md: гараж (этап 1), обновления (2–3), поиск (4), загрузка (5).
   Перед каждым экраном нарисовать недостающие состояния (раздел 3.4).

## 5. Правила на время заморозки

- Никаких новых функций и экранов.
- Документы можно исправлять, если найдена ошибка. Если в документе помечено «не проверено», не превращать
  это в утверждение без проверки на Windows.
- Тесты должны оставаться зелёными: перед любым коммитом ядра `Пройдено: 456, провалено: 0` (или больше).
