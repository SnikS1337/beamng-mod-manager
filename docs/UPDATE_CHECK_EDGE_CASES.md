# Проверка обновлений: краевые случаи и принятые решения

Интерфейс запускает проверку только через `UpdateCoordinator.CheckAsync`. Всё ниже покрыто тестами (`UpdateRunnerTests`, `UpdateCoordinatorTests`).

## Серия нажатий

| Ситуация | Что происходит |
|---|---|
| Нажали дважды / нажали, пока идёт проверка | Вторая не запускается, возвращается та же задача. «Принудительно» во время обычной проверки тоже присоединяется |
| Нажали сразу после завершённой | Сайты не трогаются (срок давности 6 ч). В отчёте `FreshSkipped` — сколько модов свежие, интерфейс пишет «проверено N минут назад», а не молчит |
| «Принудительно» подряд | Чаще раза в минуту возвращается прошлый отчёт (`Reused`). Иначе сбрасывается кэш страниц (иначе вернулась бы копия получасовой давности) и срок давности игнорируется |
| Отменили | Не исключение, а отчёт с `Cancelled`; уже проверенное сохранено. Отменённая проверка не считается «недавней» |
| Закрыли окно во время проверки | То же, что отмена |
| Исключение внутри проверки | Координатор не остаётся «занятым» |
| Читаем библиотеку из окна, пока идёт проверка | Хранилище защищено блокировкой; SQLite-версия должна давать то же (транзакции) |

## Сбои сайтов

| Ситуация | Решение |
|---|---|
| Проверка «вы человек?» | Сайт помечается `NeedsHumanCheck` и пропускается всеми проверками, пока не вызван `ResolveHumanCheck(сайт)` после прохождения проверки в окне. Остальные сайты проверяются |
| Сайт недоступен / любое исключение адаптера (сеть, таймаут, разбор) | Сбой касается только этого сайта. Следующие 5 минут он не опрашивается, сколько бы раз ни нажимали; «принудительно» паузу снимает. Прошлые данные и найденные раньше обновления остаются |
| Таймаут HTTP (TaskCanceledException без нашей отмены) | Это сбой сайта, а не отмена пользователя |
| Пустая лента | Пометка «возможно, изменилась вёрстка»; моды проверяются через карточки |
| Карточки не найдены у многих подряд | Пометка «изменились адреса или вёрстка» вместо «всё удалили» |
| Карточки нет у одного мода (404) | В отчёте «пропал с сайта»; прошлое состояние не трогается |

## Данные

| Ситуация | Решение |
|---|---|
| Мод или привязку удалили во время проверки | Без падения, состояние проверки для удалённого не сохраняется |
| Версия на карточке не разобралась (null) | Известная прежняя версия не затирается |
| Часы переведены назад («проверено в будущем») | Такая запись считается устаревшей, проверка не блокируется |
| Первая проверка 200 модов | Версия берётся из ленты (без карточек); раньше потребовалось бы ~8 нажатий по 25 карточек |
| Много модов отложено лимитом карточек (25 на сайт) | Отчёт не `Complete`, у сайта `Postponed`; повторное нажатие продолжает с оставшихся |
| Проверка слишком долгая | Лимит времени (10 мин): остановка с `StoppedByTime`, остаток при следующем нажатии |
| Два адаптера с одним идентификатором | Берётся первый, без падения |
| Привязка к сайту без адаптера | Пометка в отчёте, остальное работает |
| Один мод привязан к двум сайтам | Показывается более уверенное обновление; сбой одного сайта не скрывает другой |
| Повторные нажатия | `NewFindings` — то, чего не было до этой проверки; старые обновления не выдаются за новые |

## Что ещё нужно учесть в интерфейсе (не в Core)

- Кнопку на время проверки не блокировать намертво: показывать «идёт проверка», с кнопкой «Остановить».
- Если `Complete = false`, не писать «всё актуально»: перечислить причину по сайтам (`Sources[].Note`).
- «Пропустить эту версию» (скрыть обновление) пока не сделано: без него одно и то же обновление показывается при каждой проверке. Нужно хранить версию, которую пользователь отклонил.
- Автопроверка по расписанию должна идти через тот же координатор, чтобы не пересекаться с ручной.
- SQLite-хранилище: транзакция на пакет записей одной проверки, чтобы закрытие программы посреди проверки не оставляло полузаписанное состояние.
- Часовой пояс дат на beamng.com не подтверждён: «Updated» из `data-time` точный, из текста — приблизительный; решения по версиям от времени не зависят.
