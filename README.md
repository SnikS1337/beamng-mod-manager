# ModManager BeamNG

Менеджер модов для BeamNG.drive (Steam, Windows) для личного использования.
Ведёт библиотеку установленных модов, следит за обновлениями, ищет по нескольким
сайтам сразу и по желанию помогает скачивать.

> **Статус: этап 1 написан — разделы «Моды», «Обновления» и «Настройки».** Ядро и логика экранов проверены (766 тестов, на Linux и
> на Windows), окно собирается и снимается на Windows в GitHub Actions в тёмном и светлом оформлении. Переключение модов
> проверено на файлах игры 0.39.4, на живой игре — частично. Что сделано и что дальше: [docs/STATUS.md](docs/STATUS.md).
> План: [docs/PLAN.md](docs/PLAN.md). Дизайн: [docs/DESIGN.md](docs/DESIGN.md).

## Как запустить

Готовая программа собирается по команде (пометка `[release]` в описании коммита или «Run workflow» на странице Actions)
и лежит в [выпусках](https://github.com/SnikS1337/beamng-mod-manager/releases/latest) этого репозитория.

1. Скачать `ModManagerBeamNG.zip` и распаковать в любую папку. Устанавливать ничего не нужно, .NET тоже.
2. Запустить `BeamModManager.exe`. Первый запуск дольше обычного: программа распаковывает себя.
3. Если Windows пишет «Windows защитила ваш компьютер» (программа не подписана): «Подробнее» → «Выполнить в любом случае».
4. Папку модов программа ищет сама (`%LOCALAPPDATA%\BeamNG\BeamNG.drive\current\mods`). Не нашла — «Указать папку» и
   выбрать папку `mods` или папку пользователя игры.

**Что умеет сейчас.**
- Раздел «Моды»: все моды из папки `mods` (и из подпапок, и скачанные в самой игре) карточками с картинкой из архива,
  фильтры, поиск по своим модам, правая панель выбранного мода («Внутри архива», «Прошлые версии» с «Вернуть»),
  включение и выключение (Пробел или кнопка), «Удалить» с «Отменить» (файл уходит в копии, фильтр «Удалённые» с
  «Вернуть»), меню карточки (правая кнопка, клавиша «Меню»).
- Раздел «Обновления»: проверка модов на сайтах (при запуске, по кнопке, раз в N часов), «Пропустить версию»,
  пропавшие страницы, «Указать страницу» и «Найти замену».
- Раздел «Поиск»: поиск сразу на нескольких сайтах, один мод с разных сайтов — одна карточка, цена словами,
  «Возможно, тот же мод» с решением навсегда, «Установленные».
- Установка из архива: перетащите zip, rar или 7z на окно — программа проверит его и покажет, что внутри и чем станет
  каждый мод (новый, обновление какого, уже стоит), и поставит по кнопке с копией прежней версии и «Отменить». С
  включённым «Разрешить загрузку модов» сама замечает скачанные моды в «Загрузках» и в добавленных папках, пока открыта.
- Раздел «Настройки» (всё применяется сразу и сохраняется между запусками в `settings.json`):
  оформление (тёмное, светлое, как в Windows), готовые наборы внешнего вида («Красиво» — жидкое стекло, «Быстро» — матовое), пять тем фона
  («Ночь», «Глубина», «Сумерки», «Лес», «Графит»), анимации, движение фона, огоньки; папка модов, порог «много включённых», копии;
  проверка новой версии программы и «Проверить сейчас»; сайты.
- Самообновление программы по кнопке (раздел «Обновление программы» ниже).
- Загрузки модов из программы пока нет (следующий этап): «Страница» и «Открыть страницу» открывают мод на сайте,
  скачанный архив в папке `mods` менеджер замечает сам.

«Выключить» и «Включить» работают как в самой игре: флажком в `db.json`; перед каждой правкой прежний файл
сохраняется рядом как `db.json.bmm-bak`. Пока игра запущена, моды переключает помощник: менеджер кладёт в `mods`
свой маленький служебный мод `bmm_bridge.zip`, и игра включает и выключает моды сама, как из своего меню. Если помощник
не отвечает, изменение ждёт закрытия игры. Моды, скачанные в самой игре (`mods/repo`) и разложенные по подпапкам,
тоже видны.

Данные программы: `%LOCALAPPDATA%\BeamModManager` (библиотека, настройки, картинки модов, `errors.log`). Удалить
программу: удалить её папку, эту папку и `mods/bmm_bridge.zip`; моды не трогаются. Та же инструкция лежит в архиве («Как запустить.txt»).

## Обновление программы

Программа сама проверяет при запуске, не вышла ли новая версия (выключатель «Проверять новую версию при запуске» в
«Настройки → Обновления», там же кнопка «Проверить сейчас»). Нашлась — над сеткой плашка «Вышла новая версия …» и кнопка
«Обновить»: программа скачивает архив (на плашке полоса, сколько скачано и сколько примерно осталось, «Отменить»),
сверяет размер и SHA-256 с описанием версии, проверяет номер версии внутри exe («Проверяем и распаковываем…»),
кладёт новый exe рядом со своим (`BeamModManager.exe.new`), через 3 с («Перезапустить сейчас» — не ждать)
закрывается, сохранив своё, ставит новый на место старого
(старый — `BeamModManager.exe.old`) и открывается уже новой. Если новая версия не смогла запуститься, возвращается
прежняя и говорит об этом; эту версию программа больше не предлагает, ждёт следующую. Повторные нажатия во время
загрузки ничего не запускают заново; версия не понижается; ходит только на GitHub и только по https.

Готовые сборки лежат в выпусках этого репозитория: `v<версия>` с `ModManagerBeamNG.zip` и `latest.json`, программа
спрашивает `releases/latest/download/latest.json`. Выпуск делается только по команде: пометка в описании коммита или
«Run workflow» на странице Actions (Actions → windows → Run workflow, там же поле версии). Версии с 0.2 короткие:
`[release 0.3]` — выпустить 0.3; просто `[release]` — следующую после последней (0.2 → 0.2.1). Старее или равной
последней сборка не выпустит. Обычные изменения проверяются тестами и сборкой, но выпусков не создают.

До 0.2 (пока репозиторий был закрытым) выпуски для самообновления лежали в отдельном `SnikS1337/ModManagerBeamNG`, и
программы тех версий спрашивают обновления там. Поэтому первый выпуск 0.2 уходит и туда — «мост»: программа до 0.2
обновляется до 0.2, а та уже смотрит сюда. Для этого в этом репозитории есть секрет `RELEASES_TOKEN` (токен с правом
Contents: write на `ModManagerBeamNG`). Когда там есть 0.2 или новее, сборка тот репозиторий больше не трогает.

## Принципы

- **Менеджер первичен, загрузка опциональна.** Всё, что связано со скачиванием, включается
  отдельной настройкой «Разрешить загрузку модов» и выключено по умолчанию.
- **Не обходим платные стены, капчи, таймеры и рекламу.** Все клики на странице
  файлообменника делает сам пользователь.
- **Платный мод показываем, но не скачиваем:** метка и ссылка на страницу автора.
- **Точность важнее полноты при объединении дублей.**
- **Один адаптер на каждый сайт.** Сбой одного источника не ломает остальные.
- **В служебный файл игры (`db.json`) пишем только флажок «включён»**, при закрытой игре и с копией прежнего файла.

## Документы: в каком порядке читать

1. **Где мы сейчас:** [STATUS.md](docs/STATUS.md): что сделано, что ждёт Windows, принятые решения, первый день на Windows.
2. **Что строим:** [PLAN.md](docs/PLAN.md): цели, источники, модель данных, этапы.
3. **Что проверить на Windows:** [PHASE0.md](docs/PHASE0.md) (что известно о сайтах и игре, что нет),
   затем [WINDOWS_SCENARIOS.md](docs/WINDOWS_SCENARIOS.md) (шаги на игре).
4. **Как выглядит:** [DESIGN.md](docs/DESIGN.md), из него [DESIGN_COMPONENTS.md](docs/DESIGN_COMPONENTS.md) (детали),
   [DESIGN_FLOWS.md](docs/DESIGN_FLOWS.md) (сценарии, сбои, окно, клавиши), [DESIGN_MOTION.md](docs/DESIGN_MOTION.md) (движение).
5. **Почему ядро устроено так:** [AUDIT.md](docs/AUDIT.md), [UPDATE_CHECK_EDGE_CASES.md](docs/UPDATE_CHECK_EDGE_CASES.md),
   [TIME.md](docs/TIME.md). Фикстуры сайтов: [tests/fixtures/README.md](tests/fixtures/README.md).

Ядро не зависит от Windows: его можно разрабатывать и тестировать на Mac и Linux на
фальшивой папке `mods`. Интерфейс и окно загрузки собираются и запускаются только на Windows.

Чистая логика без внешних пакетов (всё проверено тестами):

## Сборка и тесты

Нужен .NET 10 SDK (окну — ещё и Windows).

```
dotnet run --project tests/BeamModManager.Core.Tests
dotnet run --project src/BeamModManager.App -- --demo design/demo   # только Windows; ещё --mode Light, --theme Deep|Dusk,
                                                                    # --page settings --section Folders, --shot файл.png
```

Тесты написаны на собственном мини-раннере без внешних пакетов (`tests/.../TestRunner.cs`),
потому что в среде разработки был закрыт NuGet. Когда доступ появится, их можно перенести на xunit
почти без изменений. Если NuGet недоступен, восстановите проекты с пустым списком источников:

```
dotnet restore --configfile <файл-конфиг-с-пустыми-источниками>
dotnet build --no-restore
```

Проект `BeamModManager.App` (WPF) не входит в `BeamModManager.sln`, чтобы решение собиралось и вне Windows; окно
собирается отдельно (`dotnet build src/BeamModManager.App`), на каждый push это делает GitHub Actions.
