# ModManager BeamNG

Менеджер модов для BeamNG.drive (Steam, Windows) для личного использования.
Ведёт библиотеку установленных модов, следит за обновлениями, ищет по нескольким
сайтам сразу и по желанию помогает скачивать.

> **Статус: этап 1 «Гараж» написан.** Ядро и логика экранов проверены (545 тестов, на Linux и на Windows), окно
> собирается и снимается на Windows в GitHub Actions, на живой игре ещё не проверено. Что сделано и что дальше:
> [docs/STATUS.md](docs/STATUS.md).
> План: [docs/PLAN.md](docs/PLAN.md). Дизайн: [docs/DESIGN.md](docs/DESIGN.md).

## Как запустить

Готовая программа собирается сама на каждое изменение в `main` и лежит в выпуске
[latest](https://github.com/SnikS1337/123/releases/tag/latest) (репозиторий приватный: скачивается, когда вошли в GitHub).

1. Скачать `ModManagerBeamNG.zip` и распаковать в любую папку. Устанавливать ничего не нужно, .NET тоже.
2. Запустить `BeamModManager.exe`. Первый запуск дольше обычного: программа распаковывает себя.
3. Если Windows пишет «Windows защитила ваш компьютер» (программа не подписана): «Подробнее» → «Выполнить в любом случае».
4. Папку модов программа ищет сама (`%LOCALAPPDATA%\BeamNG\BeamNG.drive\current\mods`). Не нашла — «Указать папку» и
   выбрать папку `mods` или папку пользователя игры.

«Выключить» и «Включить» работают как в самой игре: флажком в `db.json`; перед каждой правкой прежний файл
сохраняется рядом как `db.json.bmm-bak`. Пока игра запущена, моды переключает помощник: менеджер кладёт в `mods`
свой маленький служебный мод `bmm_bridge.zip`, и игра включает и выключает моды сама, как из своего меню. Если помощник
не отвечает, изменение ждёт закрытия игры. Моды, скачанные в самой игре (`mods/repo`) и разложенные по подпапкам,
тоже видны. Загрузки, обновлений и поиска в этой сборке ещё нет.

Данные программы: `%LOCALAPPDATA%\BeamModManager` (библиотека, настройки, картинки модов, `errors.log`). Удалить
программу: удалить её папку, эту папку и `mods/bmm_bridge.zip`; моды не трогаются. Та же инструкция лежит в архиве («Как запустить.txt»).

## Принципы

- **Менеджер первичен, загрузка опциональна.** Всё, что связано со скачиванием, включается
  отдельной настройкой «Разрешить загрузку модов» и выключено по умолчанию.
- **Не обходим платные стены, капчи, таймеры и рекламу.** Все клики на странице
  файлообменника делает сам пользователь.
- **Платный мод показываем, но не скачиваем:** метка и ссылка на страницу автора.
- **Точность важнее полноты при объединении дублей.**
- **Один адаптер на каждый сайт.** Сбой одного источника не ломает остальные.
- **В служебный файл игры (`db.json`) пишем только флажок «включён»**, при закрытой игре и с копией прежнего файла.

## Документы: в каком порядке читать

1. **Где мы сейчас:** [STATUS.md](docs/STATUS.md): что сделано, что ждёт Windows, принятые решения, первый день на Windows.
2. **Что строим:** [PLAN.md](docs/PLAN.md): цели, источники, модель данных, этапы.
3. **Что проверить на Windows:** [PHASE0.md](docs/PHASE0.md) (что известно о сайтах и игре, что нет),
   затем [WINDOWS_SCENARIOS.md](docs/WINDOWS_SCENARIOS.md) (шаги на игре).
4. **Как выглядит:** [DESIGN.md](docs/DESIGN.md), из него [DESIGN_COMPONENTS.md](docs/DESIGN_COMPONENTS.md) (детали),
   [DESIGN_FLOWS.md](docs/DESIGN_FLOWS.md) (сценарии, сбои, окно, клавиши), [DESIGN_MOTION.md](docs/DESIGN_MOTION.md) (движение).
5. **Почему ядро устроено так:** [AUDIT.md](docs/AUDIT.md), [UPDATE_CHECK_EDGE_CASES.md](docs/UPDATE_CHECK_EDGE_CASES.md),
   [TIME.md](docs/TIME.md). Фикстуры сайтов: [tests/fixtures/README.md](tests/fixtures/README.md).

Ядро не зависит от Windows: его можно разрабатывать и тестировать на Mac и Linux на
фальшивой папке `mods`. Интерфейс и окно загрузки собираются и запускаются только на Windows.

## Что уже есть в ядре

Чистая логика без внешних пакетов (всё проверено тестами):

| Модуль | Что делает |
| --- | --- |
| `Text/TitleNormalizer`, `TitleParser` | Название, версия мода и версия игры из заголовков сайтов («МОД … ДЛЯ BEAMNG.DRIVE» и др.) |
| `Pricing/PaidDetector` | `Paid` / `Free` / `Unknown`; «бесплатно» только при положительных признаках |
| `Hosts/HostLinkParser` | Идентификатор файла на ModsFire и MediaFire (одинаковый ID = один файл) |
| `Matching/DuplicateMatcher` | Один ли это мод на разных сайтах; по одному названию автоматически не склеивает |
| `Versioning/*` | Сравнение версий и решение «есть обновление» (`Likely` / `Possible` / `None`) |
| `Safety/ArchiveInspector` | Проверка ZIP: zip-slip, исполняемые файлы, архивные бомбы, структура мода |
| `Updates/UpdateCheckPlanner` | Сколько запросов тратить на проверку обновлений: сначала ленты сайтов, потом карточки только нужных модов, лимиты, TTL, частота по возрасту мода (200 модов укладываются примерно в 100 запросов) |
| `Install/ModInstaller`, `Profiles` | Установка ZIP в папку `mods` после проверки безопасности, замена с резервной копией, отключение/включение (файл переезжает в папку менеджера), удаление в резервные, список копий и возврат любой из них, удалённые моды; профили (в ядре есть, интерфейс не использует); проверено на фальшивой папке |
| `Game/GameModDb`, `GameInfo` | `db.json` игры (проверено на 0.39.4): какие моды включены, данные модов из репозитория BeamNG; включение и выключение флажком при закрытой игре; версия игры; папка пользователя из `startup.ini` |
| `Library/GameDbSync` | Сверка библиотеки с `db.json`, точная привязка модов из репозитория к beamng.com, «Включить/Выключить» (флажок, запасной путь — перенос файла) |
| `Library/VersionHistory` | «Прошлые версии» мода (в том числе под прежними именами файла), возврат версии, «Удалённые моды» и их возврат |
| `Library/LibrarySync` | Сверка библиотеки с папкой модов: новые, исчезнувшие, переименованные, изменённые вручную |
| `Library/BindingActions` | «Не проверять этот мод» и его отмена |
| `Matching/MatchDecisions` | Ручные решения «Это один мод» / «Это разные», хранятся навсегда (JSON) |
| `Packs` | Состав ZIP (машины, карты), пересечение пака с установленными модами, дубли среди включённых |
| `Sources/BeamNg` | Официальный репозиторий beamng.com/resources: лента по Last Update, карточка (Unique ID, размер, прямая ссылка) |
| `Library/UpdateRunner` | Кнопка «проверить обновления»: ленты, затем карточки по плану, отчёт по сайтам, отмена, сбой одного сайта не ломает остальных |
| `Sources/Adapters/SiteAdapters` | Адаптеры `IModSource` для Modland, STMods, ModsGaming и репозитория BeamNG поверх сетевого слоя (поиск, лента по страницам, карточка); поиск есть у всех, кроме репозитория BeamNG (нет образца страницы результатов) |
| `Library/BindingSuggester` | Подбор привязки установленного файла к записи на сайте: название из имени файла, ранжирование, автоподтверждение только при уверенном совпадении |
| `Search/SearchService` | Общий поиск: параллельно по всем источникам, одна карточка на мод, источники и цена каждого внутри, «возможно то же» помечается и не склеивается, сбой или зависание сайта не ломает остальные |
| `Net/PageFetching` | Вежливая загрузка страниц: очередь на сайт, пауза с разбросом, повтор после 429 с Retry-After, кэш, остановка сайта при странице проверки и после серии сбоев; проверена на фальшивых ответах с искусственными часами |
| `Library/*` | Библиотека модов, привязки к сайтам, состояние проверок; хранилище `ILibraryStore`: в памяти (тесты) и в файле `JsonLibraryStore`; список обновлений считается при чтении |
| `Game/GameModDb`, `GameInfo`, `Library/GameDbSync` | `db.json` игры: чтение, включение и выключение флажком при закрытой игре, данные модов из репозитория; версия игры; папка пользователя из `startup.ini` |
| `Previews/*` | Картинка мода из архива по оглавлению ZIP, размер по заголовку без декодирования, кэш картинок |
| `Ui/Garage/*` (проект Ui) | Экран «Гараж» без окна: карточки, фильтры, поиск по гаражу, правая панель, включение и выключение; `LibraryGarageBackend` поверх настоящих папки и `db.json` |
| `Library/UpdateCoordinator`, `BindingRepair`, `UpdateCheckService` | Единый вход проверки обновлений (повторные нажатия, отмена, свежесть), починка потерянных привязок, «Пропустить эту версию» |
| `Updates/FeedCoverage` | Когда официальная лента репозитория доказывает, что мод не менялся |
| `Settings/*` | Настройки (загрузка выключена по умолчанию, внешний вид, окно), готовые наборы внешнего вида, политика загрузки `DownloadPolicy`, папки игры |
| `Sources/SourceStatus` | Состояние источника, распознавание страницы проверки Cloudflare |
| `Sources/IModSource` | Контракт адаптера сайта |
| `Sources/Modland`, `ModsGaming`, `StMods`, `ModsFire` | Разбор страниц (список, поиск, карточка); без сети, проверен на сохранённых настоящих страницах. Сетевой слой: `Net/PageFetching` (`HttpPageFetcher`), на живых сайтах не проверен |

## Сборка и тесты

Нужен .NET 8 SDK (окну — .NET 10 SDK и Windows).

```
dotnet run --project tests/BeamModManager.Core.Tests
dotnet run --project src/BeamModManager.App -- --demo design/demo   # только Windows
```

Тесты написаны на собственном мини-раннере без внешних пакетов (`tests/.../TestRunner.cs`),
потому что в среде разработки был закрыт NuGet. Когда доступ появится, их можно перенести на xunit
почти без изменений. Если NuGet недоступен, восстановите проекты с пустым списком источников:

```
dotnet restore --configfile <файл-конфиг-с-пустыми-источниками>
dotnet build --no-restore
```

Проект `BeamModManager.App` (WPF) не входит в `BeamModManager.sln`, чтобы решение собиралось и вне Windows; окно
собирается отдельно (`dotnet build src/BeamModManager.App`), на каждый push это делает GitHub Actions.
